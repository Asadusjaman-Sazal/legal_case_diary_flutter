## Current Version:
Version: 0.0.220 - Bug fix: a Bengali printout failed with "Could Not Print" while the English one worked, and the fault was layout, not the PDF. Bengali is the only path that draws the raster capture, and the progress dialog parents that capture with a `Positioned(left: -2000, top: 0)` - no `top`/`bottom`, so its child is handed **unbounded** constraints. The capture's root `Stack` sizes itself to `constraints.biggest` and asserts `size.isFinite` on those, so the capture subtree never laid out, `_measureBlocks` threw on its first `child.size`, and `print_flow.dart` turned the throw into `PrintOutcome.failed`; the host was blind to it because the Phase 2 tests mount the capture straight under a `Scaffold`, where the parent hands it tight constraints. `PrintPageCapture` now wraps its content in a `LimitedBox` - which bounds only what the parent left unbounded and passes a bounded parent through untouched - so a page is never clamped to the parent's height and the blocks keep the natural heights the paginator measures. Two hardenings in the same file: a capture failure is now logged with its stack instead of vanishing into `PrintOutcome.failed`, and the block measurement throws a readable `StateError` rather than an assertion about an anonymous render box. Tests: new `print_bengali_dialog_test.dart` (3) drives the real path - `captureDocumentInDialog` with the engine's own `encodePagePng` and the real isolate assembler - and asserts that a Bengali document produces a one-page `%PDF` and closes its dialog, that a captured Bengali page carries ink rather than being blank (decoded and counted, the silent failure of any offscreen-paint capture), and that a capture parented by a dialog-style positioned child still lays out. `flutter analyze` clean; `flutter test` 469 passed, 2 skipped.
Version: 0.0.219 - Task 14 Phase 5 complete: every search runs on the Drift `LIKE` path. `CasesDao.searchScoped` is the one field set - case number, both parties, both lead counsels, the represented role row resolved through `on_behalf_id`, the party phone, the case title/section and the remarks - applied **inside** the screen's own dataset predicate: the new `CaseSearchScope` / `CaseSearchDisposal` (`features/cases/data/case_search_scope.dart`) carry any / active / disposed plus an inclusive `next_date` window, and the query keeps the standard `is_deleted = 0` filter and the repository's `limit` / `offset` paging; the old `search()` now delegates to it. Every nullable column is guarded `IS NOT NULL AND LIKE ...` instead of `IS NULL OR LIKE ...`, because the OR form made a NULL column match **every** row and the first screen test got the whole table back. `CaseRepository.searchScoped` exposes it, and the six case screens, Notes and Case References each hold one `ScopedSearch<T>` (`core/utils/scoped_search.dart`): a blank query restores the screen's own dataset synchronously, and a slow query can never overwrite a newer one's result, so the in-memory `matchesCaseQuery` matcher is gone. Notes search now goes through `NotesDao.search` (title and body) and Case References through `CaseReferencesDao.search` (all five text fields); the Settings search already filtered its localized labels. Tests: `case_list_search_test.dart` gained a `CasesDao.searchScoped` group (the field set, dataset predication and both date windows, soft-delete plus paging, and the client-name rule) and a widget test proving the bar queries the **database** rather than the rows the screen happened to load (a case saved after the screen loaded is found, and closing the bar restores the dataset), replacing the old pure-matcher tests. `flutter analyze` clean; `flutter test` 466 passed, 2 skipped.
Version: 0.0.215 - Task 14 Phase 1 complete: the PDF print core. `pdf`, `printing` and `share_plus` added - they were never in `pubspec.yaml`, so Task 01 Phase 2 deferred them. New `lib/core/print/`: (1) `print_document.dart` is **pure Dart** - no plugin, no Flutter, no database - and holds the canonical print layout every case screen shares (case number and case type heading, then Court on the flat lists only, Petitioner, Respondent, Lead Counsel, On Behalf, Step, the screen own date column and Note; blank values are left off the page; serials are localized and appear only on the screens that show them), plus the localized footer and page counter. It also owns the decision that matters most: **needsRaster**, because `pdf` 3.13.0 ships no Indic shaper (its only shaping table is `arabic.dart`), so Bengali conjuncts, reph and pre-base vowel signs come out visually wrong while still extracting as text - a document containing Bengali must therefore go to the bounded raster renderer (Phase 2) instead of the native text path, while a Latin-only document keeps searchable text. (2) `pdf_native_renderer.dart` registers all four bundled fonts (Inter body, Manrope headlines, IBM Plex Sans data and **Tiro Bangla** for every Bengali run, reached through the theme font fallback) and paginates with `pw.MultiPage`, so pages break on measured height rather than a row count. (3) `print_service.dart` is the platform boundary and the only file importing `printing`, so screens and tests never touch the plugin. Two ARB keys in both languages (`print_printedOn`, `print_pageOf`). Tests: new `print_document_test.dart` (10: field order and blank handling, the flat-versus-grouped court rule, localized labels, footer, page counter and serials, and the script-aware decision), new `pdf_native_text_test.dart` (6: all four fonts load, Tiro Bangla has a glyph for every fixture character, **the printed Bengali characters round-trip out of the ToUnicode map the file itself writes, in draw order**, the embedded font is TiroBangla-Regular rather than a substitution, and 3 rows fit one page while 200 rows produce several, which is measured breaking rather than a row count) and new `print_platform_boundary_test.dart` (4 source guards: only the print service imports the plugin, the model stays pure, the print path stays offline). Flagged: the task asked for golden/text-extraction checks and the `pdf` package ships no extractor, so extraction is verified through the font cmap and that ToUnicode map instead. `flutter analyze` clean; `flutter test` 424 passed, 2 skipped.
