## Phase 2 — `cases_screen_modal.dart` (Reusable Case-Screen Shell)

Per the folder-structure note, this reusable layout provides for every case screen:
1. Side **navigation panel button** + the panel itself (`app_navigation_drawer.dart` — Daily Cause List drawer template from the mockup; option visibility driven by `side_nav_options`; includes Case screens, Notes, References, Share, Print, etc.). **The panel's last line shows the bundled app version (0.0.408, user request)** — e.g. `V0.0.408`, read from `appVersion` so it can never drift from the build, carried by the `drawer_version` ARB key as a Latin `V{version}` token in both languages (a version identifier is not translated). **(0.0.409)** It is pinned to the very bottom of the panel's available space — a footer below the scrolling list rather than a row inside it — and is left aligned, per the user's follow-up. **(0.0.428, user request; position moved 0.0.429.)** The panel also carries the account's **current plan**, as one row in the **Print/Share** group, directly above **Print** (the user first asked for it under Settings and then moved it here): it names the plan (`Free`, `Premium`, or the paid plan's name) with a **Current Plan** caption, and expands on tap — **not** by navigating — into **Subscription Details** and **Subscription Plans**, each of which opens the screen it names and closes the panel like every other item. The plan comes from `currentPlanProvider` (`features/payments/presentation/current_plan.dart`), the same derivation Subscription Details prints, so the entitlement rule and the *dash until entitlement lands* rule live in one place; the row is always shown (no `side_nav_options` key) and the panel has no mockup to follow. **(0.0.431, user request; anchored to the icon in 0.0.432.)** The panel's **profile icon** — the header avatar, a 48 px `InkWell` with a `Semantics(button: true)` label — opens the **account popover**: the address the account signed in with, captioned with the existing `auth_emailLabel`, then **Profile** (→ `/settings/profile`), **Manage Account** (→ `/settings/manage-account`) and **Logout**. The three rows reuse `settingsScreen_profile`, `settingsScreen_manageAccount` and `settingsManageAccount_logout`, so the panel adds no ARB key; **Logout** runs the app's one branched logout (`runBranchedLogout`) and lands on **Login** explicitly, as Manage Account's card does. **The panel is anchored to the icon** (0.0.432, user request — *“like Google does in their various app”*): its top edge 8 px under the icon's bottom, its left edge on the icon's left, placed by a `SingleChildLayoutDelegate` from the icon's own rectangle measured in the root navigator's overlay. It replaced the 0.0.431 `showModalBottomSheet`, which rose from the screen's foot; it is a `PopupRoute` with a **transparent barrier** (tap outside dismisses, no dimming), `AppSpacing.cardRadius`, elevation 8, a 150 ms fade and scale from its top-left, and a 300 px width (less twice an 8 px inset when the screen is narrower). The measurement is why the avatar is its own widget (`_ProfileIconButton`): a composite element's `findRenderObject` descends to the first render object below it, which is the avatar's 48 px circle. A chosen row **closes the panel and the drawer**, so a dismissed panel returns the user to the panel and a chosen row to the screen behind it. It is a **widget with its own `ref`** rather than a closure over the panel's, because the logout reads providers and opens windows and the drawer's `ref` dies with the panel — the close-then-act shape was written, tested and rejected (`Using ref when a widget is about to or has been unmounted is unsafe`); the two navigators therefore reach it as state objects. `app_navigation_drawer_test.dart` covers the anchoring, the e-mail, the two routes and the logout. **(0.0.433, three user follow-ups.)** The panel now lines up with the side menu — its left edge is the **drawer's own left edge** rather than the icon's, and **(0.0.434, user request)** its width is the **drawer's own width**, taken from the drawer's measured box at tap time, so it is neither narrower nor wider than the side menu it opens over; it carries a **1 px `AppColors.outlineVariant` edge**, so a white menu over the white drawer is visibly floating above it; and the avatar carries a **16 px chevron badge** in its bottom-right corner — the panel's own fill, the same divider grey and the plan row's `expand_more` — an affordance that leaves the picture and the tap target alone. **(0.0.435, user request — a Gmail account-switcher screenshot attached.)** The panel's **window and option block** were restyled after the reference: a **rounded window** whose corners are 16 px (`_accountPopoverRadius`) rather than the 4 px card radius, keeping the 1 px `AppColors.outlineVariant` edge the user asked for by name; the address line's **`auth_emailLabel` caption dropped**, since the `alternate_email` icon already says what the line is; and the three options rebuilt on the drawer's own **`_DrawerNavTile`** (which gained a `key` parameter) so they form a block of **transparent rows** reading at exactly the side menu's metrics — 22 px icon, 16 px icon gap, `AppTypography.labelLg` at w500 in `onSurfaceVariant` — with 8 px of air under the last row. Their labels are unchanged; only the window's shape and the rows' metrics moved. **(0.0.443, user request.)** The account popover is **inset a little on each side**: its width is the drawer's less twice `AppSpacing.sm` (8 px; halved from 16 px in 0.0.444) and its left edge is the drawer's plus that inset, so both its edges are visible inside the side menu. This supersedes the 0.0.434 width-is-the-drawer's rule at the user's request. **(0.0.450, bug fix — the device's Logout crash; also recorded in the plan.)** The panel's email, its `NavigatorState` and its `GoRouter` are read **at open time** while the drawer is certainly mounted, not inside the route's `builder` closure. That closure re-runs on every rebuild of the panel's page, and **Logout closes the screen the drawer lived on**, so the next rebuild read the deactivated drawer's `ref` and threw `Using "ref" when a widget is about to or has been unmounted is unsafe` — reported as *building Builder* (a `PopupRoute`'s page is built inside `_ModalScopeState`'s own `Builder`). `app_navigation_drawer_test.dart` is now 19 cases, the new one over a shell-shaped router. **(0.0.451, user request.)** **Logout no longer closes the side menu.** The popover's Logout row dropped its leading `_closeDrawer()`, so the drawer and its account panel stay up while the branched logout's windows run above them — a cancelled branch leaves the user exactly where they were, still able to pick another action — and the panel is closed only once the flow has finished (before the explicit `go(Login)` when it completed). This also keeps the panel's `ref` and its measured geometry mounted for the whole flow. `app_navigation_drawer_test.dart` is now 20 cases: the new one opens the drawer, taps Logout, and asserts the drawer's own row *and* the confirmation window are both on screen before the flow proceeds. **(0.0.454, user request — the slow logout's feedback.)** The Logout row now answers the tap at once: `_AccountPopover` became a `ConsumerStatefulWidget` with a `_loggingOut` flag, and `_DrawerNavTile` gained a `busy` flag that replaces the row's leading icon with a 22 px `CircularProgressIndicator` for the flow (cleared in a `finally`); re-taps are ignored. This is the drawn feedback for a logout that legitimately takes seconds (wipe + reseed + sign-out), so it never reads as a dead button. The two dialog-branch logout tests pump a bounded window because `pumpAndSettle` cannot settle an indeterminate spinner; a new test holds the flow with a `Completer`, asserts the spinner, releases it and asserts Login. Suite is now 21 cases.
2. Page header with title, **search button**, view toggles, and the real **manual Sync button** at top-right on every case screen. Expose accessible idle, syncing, success, paused, and error states. In Part A or without entitlement, keep the control visible but disabled with a localized entitlement explanation; do not implement placeholder-only behavior or speculative copy. **The view toggle became functional in 0.0.203** — it is rendered only when the host screen wires `onViewToggle` (so it is absent on Notes and Case Reference, which use this shell but have no case list) and it reads/writes a **per-screen** mode (`case_list_display_modes`, a screen the user has never switched falling back to the global `case_list_display_mode` since 0.0.205); the extended view it switches to is specified in `docs/tasks/08_case_list_screens.md` Phase 6 — since 0.0.204 a spreadsheet-style table with one header row (`CaseTableHeader`) over value-only rows, resizable columns stored per user.
3. **Bottom nav bar** (`bottom_nav_bar.dart`): 4 configurable tabs, defaults Overdue Dates / Daily Cause List / Active Cases / Upcoming Cases, customizable via View Settings (`bottom_nav_tabs`).
4. **FAB (Add New Case)** on all main case screens **except Disposed Cases**.
5. **Print** and **Share** are separate actions (Share invokes the Android native share utility to share the app; Print is Task 14).
6. **Back on a destination offers Exit, never a pop (0.0.383).** Every screen built on this shell answers the system back gesture with the `Exit App?` window (`AppShellRoot.requestExit`) rather than returning to the screen the destination was opened from — the drawer and the All Cases summary cards push these routes, so a pop would land somewhere unrelated to the tab. An open drawer still closes on the first back; the window is unchanged, only when it appears. This extends Dev Workflow §6 (Phase 1 item 3) from the root screen to the destinations themselves.
7. **The exit is the host's close, not the framework's pop (0.0.422 — user bug report).** `SystemNavigator.pop()` does **not** finish the Android activity on this Flutter: the engine turns it into an Android back press, and a back press at the root of the task only backgrounds the app — so Exit App? left the app in memory like the home button. `AppShellRoot`'s confirm and `requestExit` now call `closeApp()` (`core/services/app_exit.dart`), which asks `MainActivity.kt` to `finishAndRemoveTask()` over its own channel (`com.legalcasediary.app/app_exit`, finished *and* dropped from recents); `SystemNavigator.pop()` stays as the fallback when no host answers, so the button is never dead. `test/core/app_shell_exit_test.dart` pins both ends: the host channel is called on confirm, and each fallback branch still reaches the framework pop.
